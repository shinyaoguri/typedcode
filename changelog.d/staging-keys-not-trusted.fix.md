本番の verify と verify-cli は、staging の環境の鍵で署名された proof を「時刻アンカー済み」と表示しなくなりました。これまでは staging の Worker が発行したセッション開始トークンと署名チェックポイントを本番の鍵と区別せずに信頼しており、staging で作った proof が本番の提出物と同じ `anchored` に見えていました。改ざんではないので、こうした proof の合否 (verify-cli の exit code) と整合性の表示は変わらず、時刻の欄が「アンカーなし」になって、staging の鍵で署名されていることが理由として出ます。staging (https://staging.typedcode.pages.dev や PR プレビュー) で作った proof を時刻アンカー込みで確かめるときは、verify-cli に `--allow-staging-keys` を付けるか、staging の verify を使ってください。本番の Worker も、staging の Worker が発行したセッション開始トークンでは署名しなくなりました。

開発者向け: 手元の `packages/shared/src/checkpointKeys/localKeys.ts` に鍵を書いている場合、配列の型を `readonly LocalCheckpointPublicKey[]` に変えてください (`import type { LocalCheckpointPublicKey } from './registry.js'`。`localKeys.ts.example` と同じ形)。`registry.ts` に鍵を足すときは `environment: 'production'` か `'staging'` を書きます。
