# packages/editor — 罠: 作問画面 (`/author`)

`authoring/` を触るときに読む。[AGENTS.md](../../AGENTS.md)「よくある罠」に見出しがあり、ここが本文 (理由・経緯・回帰テスト)。罠を足すときは、ここに本文を書き、AGENTS.md には見出しを 1 行足す。

`core/`・`services/`・`ui/` などで始まるコードのパスは `packages/editor/src/` から見たもの。

- **教材フォルダのハンドルはセッション DB と別の IndexedDB に置く (#795 / ADR-0051)**: `/author` が開いた教材フォルダの `FileSystemDirectoryHandle` は `authoring/workspace/folderHandleStore.ts` が `typedcode-author-workspace` に保存する (直近の 1 つだけ。操作ごとに open して close する)。モード別のセッション DB の名前空間に入れず、モードのリセット (`clearCurrentModeData`) で消えない。**署名鍵・監督コードはここにも教材フォルダにも書かない** (ADR-0051 D7)。再訪時は `folderAccess.ts` の `resumeMaterialFolder` が `queryPermission` を見て、`prompt` なら読み書きせずに `needs-permission` を返す。Chrome の `requestPermission` はユーザー操作の中でしか通らないので、**返された `grant()` はクリックのハンドラの中で呼ぶ**。保存は `MaterialFolder.writeText` が読んだときの `lastModified` と比べ、外部で変わった・消えた・このオブジェクトが読んでいないファイルが在る場合は、書かずに `conflict` を返す (承知で書くのは `{ overwrite: true }`)。同期ソフトが内容を変えずに `lastModified` だけ進めた場合も競合になる。新規ファイルの最初の書き込みが失敗すると、空のファイルが残りうる (保存し直しは競合にならない)。パスは教材フォルダの根からの相対 POSIX パスで、`MaterialFolder` は `workspace/` の純関数が読む `WorkspaceReader` (`readText` / `exists`) を構造的に満たす。verify の `FileSystemAccessService` (読み取り専用) とは共通化しない
- **教材フォルダの定義ファイルは `authoring/workspace/definitions.ts` を通して書く (#794 / ADR-0051)**: ケースの `stdin` / `stdout` は 1 文字も変えずに往復させる約束だが、`yaml` (2.9) に任せると、全行が空白だけの値 (`" \n"` など) をインデント指示子の無い `|+` で書き、読み戻すと値が変わる。`createCasesDefinitionText` / `updateCasesDefinitionText` は書いた後に読み直して全ケースを照合し、ずれた値だけ二重引用符で書き直す (それでも合わなければ `unstable-value` で失敗を返す)。**`yaml` の `stringify` を直接呼んでケースを書かない**。書き戻しは変えたキーだけを差し替え (コメント・未知のキー・flow の書き方を残す)、変化が無ければ元のテキストをそのまま返す。未知の `format` は読みも書き戻しもしない。型は厳格で、`stdout: 8` (数値) や `public: yes` (YAML 1.2 では文字列) は変換せず `invalid-type` にする。配布物の starter の `language` は `authoring/starterLanguage.ts` が正本 (shared の `getLanguageFromExtension` とは対応が違うので混ぜない。既存の配布物と同じ値を保つため)。`updateCasesDefinitionText` の第 3 引数 `sources` は、新しい並びの各ケースを、元のファイルの何番目のケースの節点 (コメントと未知のキーごと) から作るかを渡す (#798)。途中のケースを消す・足すときは必ず渡す (省くと添字で対応させるので、後ろのケースのコメントと未知のキーが前のケースへずれる)
- **作問画面の状態は `AuthorWorkspace` に置き、開いている文書のファイルを裏で読み直さない (#796 / ADR-0051)**: `MaterialFolder.readText` は読むたびに「読んだときの `lastModified`」を覚え直す。開いている文書のファイルを、索引の読み直しや書き出しのために裏で `readText` すると、外部の変更を読んだことになり、次の保存が競合にならずに上書きする。索引 (`refresh`) と書き出し (`buildExamBundle`) は、開いている文書については文書の保存済みのテキストを使う。未保存の文書が 1 つでもあれば書き出さない。学生プレビュー (`previewExam`) だけは、開いている文書の今のテキスト (未保存を含む) を重ねて読む。**パスの照合は NFC にそろえて行い、I/O は一覧の綴りで行う** (macOS や同期フォルダは濁点を分解した NFD の名前を返すことがある。定義の参照と突き合わせるときだけ `normalize('NFC')` し、ファイルに書く綴りと API に渡すパスは元のまま)。**問題定義の書き戻し (「追加」「既存のファイルを選ぶ」) はその場で保存する**: ディスクの今の定義を読んで patch し、すぐ書く。その定義を文書として開いていて未保存の編集があるときは、書かずに `definition-dirty` を返す。問題の作成は本文を先に、定義を後に作るので、定義の作成だけが失敗すると本文のファイルが残る (「追加」も同じで、新しいファイルが残る)。書き出しの対象は、選んだ試験定義が採用した問題 (出題順) だけ (#797)。examId・種類・許可言語は試験定義から取り、フォルダには何も書かない。試験定義のフォームの操作は、文書のテキストを `updateExamDefinitionText` で書き換える (未保存の編集として扱い、コメントと未知のキーを残す)。**署名鍵・監督コードは書き出しのパネルの入力欄にだけ置き (種類が試験のときだけ出す)、教材フォルダ・IndexedDB・localStorage に書かない**
- **ファイルの種類ごとの表示は `authoring/ui/documentViews.ts` に登録する (#797)**: `DOCUMENT_KINDS` に `{ id, matches(path), views, defaultView }` を足すと、`EditorArea` がその種類の文書に表示の切り替え (群の `data-view`、ツールの `data-action="view-<名前>"`) を出す。`mount` を持たない表示は Monaco、持つ表示は `ViewContext` (`path`・`host`・`workspace`・`setView`) を受けて `ViewInstance` (`update`・`dispose`) を返す部品で、文書や索引が変わるたびに `update` が呼ばれる。狭い一致 (接尾辞 `.exam.yaml`) を広い一致 (拡張子) より前に置く。**`EditorArea` に種類ごとの分岐を足さない** (種類を足すのは部品 1 つと登録 1 行)。フォームのような表示は文書のテキストを書き換えるだけにし、保存・未保存の印・競合は他の文書と同じ経路に任せる
- **問題のコピーは保存済みの内容から作り、コピー先を覚えない (#800 / ADR-0051)**: 画面からのコピー (`workspace/problemCopy.ts`) は、コピー元を `AuthorWorkspace.reader()` (開いている文書は保存済みのテキスト) で読む。問題定義とその参照ファイルに未保存の文書があれば、コピーせずにパスを知らせる (関係ない文書の未保存では止めない)。**止める判定 (`problemCopyBlocker`) はピッカーを開く前に同期で行う** (クリックからピッカーまでの間に await を挟むと、Chrome はユーザー操作の外とみなしてピッカーを拒否する)。**コピー先のフォルダは `FolderHandleStore` に保存しない** (今開いている教材フォルダの再開先を変えない)。今開いているフォルダをコピー先に選んだ場合は `isSameEntry` で見分けて何も書かない。書き込みの途中で失敗すると、失敗したパスに空のファイルが残りうる (`copyProblem` は取り消さない)
- **ケースファイルのフォームは、利用者が触った欄だけを文書に書く (#798)**: `authoring/ui/CasesFormView.ts` は、`input` / `change` が起きた欄だけを `workspace/casesForm.ts` の `edit` (patch に挙げた欄だけを変える) で文書のテキストに書く。テキストエリアは値の改行を LF にそろえるので、再描画や選択の切り替えで欄の値を書き戻すと、触っていない値の CRLF が LF に変わる。欄で編集した値の改行は LF になり (値が `\r` を含む欄には注記を出す)、CRLF のまま書きたいときはテキストの表示で書く。名前が空・重複の間は文書を書き換えず、欄の下に誤りを出す。フォームになるのは接尾辞が `.cases.yaml` のファイルだけ (問題定義の `cases:` が別の名前のファイルを指す場合は、テキストで開く)
