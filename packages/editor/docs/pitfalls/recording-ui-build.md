# packages/editor — 罠: 入力の記録・ダイアログ・起動・ビルド

IME と Monaco のイベント、ダイアログ、起動時の処理、対応ブラウザの判定、Vite の設定を触るときに読む。[AGENTS.md](../../AGENTS.md)「よくある罠」に見出しがあり、ここが本文 (理由・経緯・回帰テスト)。罠を足すときは、ここに本文を書き、AGENTS.md には見出しを 1 行足す。

`core/`・`services/`・`ui/` などで始まるコードのパスは `packages/editor/src/` から見たもの。

- **`vite-plugin-top-level-await` を再導入しない (#255)**: このプラグインはチャンクの全エクスポートを先頭の `let` に巻き上げて本体を async IIFE で包む。`export function` が代入文に降格するため、**関数宣言の巻き上げに依存している monaco** (`vs/platform/instantiation`: `createDecorator` を定義より前に呼ぶ) が壊れ、`createDecorator is not a function` → 以降のエクスポート代入が全て飛び `Class extends value undefined` に至る。**dev サーバでは再現せず本番ビルドだけが壊れる**ので、`packages/e2e/tests/production-build.spec.ts` (vite preview 対象) が番人。`build.target` を `esnext` から下げるときだけ再検討の余地がある
- **ダイアログは `ui/components/dialogA11y.ts` の `attachDialogA11y` を使う (#305)**: `role` / `aria-modal` / `aria-labelledby`・初期フォーカス・Tab トラップ・Escape・起点へのフォーカス復帰を担う。document の keydown リスナーは `close()` でしか解放されないので、**閉じる経路 (ボタン・overlay・Escape) を 1 つの冪等な close 関数に集約して、その中で呼ぶ** (経路ごとに外すと取りこぼし、開閉のたびに古い Escape ハンドラが溜まる)。起点がメニュー項目なら、ヘルパが `aria-controls` を辿ってメニューを開いたボタンへ戻す (消えかけの項目は `focus()` が一度成功したあと body に落ちる)。**メニューボタンには開く popup の id を `aria-controls` で付ける**。ネイティブ `<dialog>` は top layer に出て `ExamStartGate` (z-index 40000) との重なりが変わるので使わない。`showModal()` は `closeOnOverlayClick: false` なら Escape でも閉じない。DOM 生成型のダイアログは移行済み (復旧・セルフレビュー・書き出し進捗・テンプレート取込・画面共有の選択 / 確認)。**選択が必須 (復旧) / 入力を持つ (セルフレビューのノート) / 進行表示 (書き出し・テンプレート進捗) は `closeOnEscape: false`、破壊的な選択肢があるときは初期フォーカスを取り消し側へ**。Turnstile の iframe は Tab 巡回の対象 (cross-origin なので中からは抜けられ、次の Tab で引き戻す)。`index.html` の静的 overlay は `showStaticDialog` で開き、返る `close()` で閉じる (`.hidden` を直に付け外ししない)。タブ閉じ確認・`CountdownDialog` / lock overlay も移行済み。閉じさせない画面 (起動を止める overlay・規約・`storage-low`・`processing`・アイドルの警告・lock) は Escape を無視する。lock / countdown は同じ id で出し直すと前の回を `overlayDisposers` で解放する。`ExamStartGate` と `ClassProblemLoader` (全画面のゲート / ローダ) も `.exam-gate-content` を名前付きの modal dialog にして移行済みで、Escape では閉じない (#743)。ファイルのドロップゾーンは div のまま `role="button"` + `tabindex="0"` にし、Enter / Space は `dropzoneKeyboard.ts` が受ける。`#clang-loading-overlay` は進捗の表示なので dialog にせず `role="status"`。**メニュー (`MainMenuDropdown` / `SettingsDropdown`) の開閉は `open` / `close` / `toggle` を通す** (ボタンの `aria-expanded` を `visible` クラスと一緒に変えるため。外から `visible` を直に外さない。#743)。**ダイアログの見出しが h3〜h6 なら `attachDialogA11y` が `aria-level="2"` を付ける** (ページの h1 = titlebar の下の 2 段目として読ませる。タグは CSS が選んでいるので替えない。#738)。移行状況の正本は `docs/accessibility-accommodation-policy.md`
- **起動時ワンショットは「セッションのスナップショット型」に登録する (#405)**: `recordToAllTabs` は記録した時点にあるタブにしか載せないので、起動時に 1 回だけ記録するイベントは、起動時にタブが無い class / assignment と 2 個目以降のタブの proof から欠落する。`EventRecorder` の `SESSION_SNAPSHOT_EVENT_TYPES` (`windowResize`・`networkStatusChange`・`environmentProbe`・`screenShareOptOut`) に入っている型は最新の 1 件を保持し、`TabManager.setOnTabCreated` (Phase 4.9 で配線) 経由で新しいタブに `recordSessionSnapshotTo` が流し直す (`termsAccepted` は main の `buildTermsAcceptedEvent` から作り、既にあるタブには重ねない。`screenShareOptOut` は `screenShareStart` が来たら保持を消す = 共有開始後のタブに opt-out を載せない)。**新しい起動時ワンショットを足すときはこの配列に登録する**。フックは `createTab` / `createTabFromTemplate` の `tabs.set` と**同じ同期区間**で呼ぶ (await を挟むと `recordToAllTabs` と二重・漏れになる)。Phase 4.9 より前に作られたタブ (casual の既定タブ・exam の開封タブ・復元タブ) と復元経路は対象外で、従来どおり Phase 5 / 5.5 で載る。状態が遷移するイベント (visibility / focus / fullscreen) は流し直さない (新しいタブは遷移に立ち会っていない)
- **IME の composition は Monaco の `onDidCompositionStart` / `onDidCompositionEnd` で取る (#720)**: Monaco 0.57 は Chromium で native EditContext を既定で使い、IME の composition のイベントは DOM 要素ではなく EditContext オブジェクトに飛ぶ。document / textarea に `compositionstart` / `compositionend` / `beforeinput` のリスナーを付けても IME の間は 1 件も届かない (実測。通常の打鍵の `beforeinput` は届く)。Monaco の `@internal` な `detailedReasons` にも頼らない
- **`editor.inComposition` で確定の編集を判定しない (#720)**: 確定の編集と compositionEnd の順は環境で違い、確定より先に false になる経路がある (CDP + EditContext では確定の change が end より前に届く)。`CompositionTracker` は start / end のイベントで自前の状態 (`idle` / `composing` / `settling`) を持ち、end の直後に対応した 1 件だけを確定 (`insertFromComposition`) とする。settling はタイマーの窓でなくタスク境界 (`setTimeout(0)`、注入可) で閉じる。model の切替・blur・flush で状態を捨てる。限界: composition 中に領域へ接する位置の直接の編集は composition に帰属する、main world のスクリプトは composition の開始を偽装できる、複数カーソルの composition は主カーソルの 1 領域だけを追う。E2E の取消は `Input.imeSetComposition('')` で行う (`Input.insertText('')` だと compositionEnd が来ず composition が開いたまま残る)
- **Monaco の `onDidChangeModelContent` イベントは ICustomEvent ではない**: `InputDetector` で paste を判定するときの DOM event は `editor.onDidPaste` 経由で取る (Monaco の paste は contentChange と paste の 2 段)
- **ビルド時に注入される `__GIT_COMMIT__` 等**: dev サーバでは undefined になることがあるので、参照側でフォールバックを持つ
- **記録させるのは Chromium 系だけ (#596 / ADR-0033)**: `initializeApp` の Phase 0.5 が `app/browserSupport.ts` の `detectUnsupportedBrowser` (UA 文字列だけを見る許可リスト) で、Chromium を名乗らないブラウザ (Safari / WebKit・Firefox・その他) を止める。Firefox を通すなら、先に nightly に Firefox の project を足す
