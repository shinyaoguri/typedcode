# packages/editor — 状態契約 (data-* 属性) の全表

[AGENTS.md](../AGENTS.md)「状態契約 (data-* 属性)」の表と本文。E2E が読む要素・属性・値域・dev フックはここが正本で、変えるときは `packages/e2e` の E2E と同じ PR で変える (末尾の「契約を変えるとき」)。

E2E (`packages/e2e`) は editor の UI 状態を、翻訳テキストや CSS クラスではなくここに挙げる **data-\* 属性** と dev 限定フック `__tcTestSnapshot` で読む ([ADR-0034](../../../docs/adr/0034-replace-manual-verification-with-automated-tests.md)、#433)。値は生の値 (id・言語 id・enum) で、翻訳しない。既存の class (`active` / `synced` など) や表示テキストはそのまま残してあり、契約はそれに**足した**もの。

| `#browser-preview` | `data-preview-state` | `rendered` / `empty` / `not-allowed` | HTML プレビューを最後に描き直した結果 (`BrowserPreviewPanel.refresh`。#727)。`empty` = HTML タブが無い、`not-allowed` = HTML タブはあるが試験の許可言語に入らないので描かない (どちらもプレースホルダー)。パネルを最初に開くまでは属性なし |

## `data-dialog` の名前

`data-dialog` の名前: `terms` / `reset` / `tab-close` / `processing` / `duplicate-instance` / `unsupported-browser` / `boot-failure` / `storage-low` (以上 `index.html` の静的要素。`boot-failure` は `initializeApp` が reject したときに `boot()` が、`main.ts` の chunk の取得や top-level の評価が失敗したときに `entry.ts` が出す (`app/bootFailure.ts`)。#325 / #302。`storage-low` は起動時の空き容量の試験で書けなかったときに `initializeApp` が出し、ボタンは `data-action="continue"` / `"retry"`。#626) / `session-recovery` / `welcome` (`.welcome-screen`) / `self-review` / `screen-share-choice` / `screen-share-optout-confirm` / `screen-share-error` / `screen-capture-lock` / `idle-warning` / `idle-suspended` / `export-progress` / `exam-gate` / `class-problem-loader` (`ClassProblemLoader`。閉じると `.hidden` が付いてから外れる) / `template-import` / `template-progress` (`TemplateImportDialog` の確認と進捗。閉じると DOM から外れる) / `unproven-content` (`UnprovenContentDialog`。復元時に証明と食い違った元のコードの通知 = #413。閉じると DOM から外れる) / `instance-conflict` (`InstanceConflictDialogs`。同じセッションを別のタブに再開された側に出す全面のブロック画面 = #237 PR-3。ボタンは `data-action="rescue"` (救出ダウンロード。押しても閉じない) / `"close"`。再読み込みまで閉じない)。`Modal.ts` の `showModal` / `showCountdownDialog` / `showLockOverlay` で作るものは引数 `dialogName` で overlay に付ける (新しいダイアログを足すときも名前を付ける)。`/author` のダイアログ (`authoring/ui/authorDialogs.ts`。#796): `new-problem` / `create-folder` / `new-exam` (名前の入力。`new-exam` は #797) / `add-part` / `assign-part` / `conflict` (保存の競合。読み直す / 上書きする / やめる) / `unsaved` (未保存の変更を捨てて進むか) / `copy-result` (問題のコピーの結果。#800。overlay に `data-copy-status` = `copied` / `conflict` / `source-invalid` / `failed` / `dirty` / `same-folder`、パスの一覧は `ul[data-copy-paths]` (`written` / `conflict` / `dirty` / `failed`) `> li[data-path]` (`failed` で書けたパスがあれば `written` と `failed` の両方)、`source-invalid` のときは `ul[data-issues]`、閉じるボタンは `data-action="close"`)。

## dev フックと E2E の読み手

- **dev フック `window.__tcTestSnapshot()`** (`main.ts` の `import.meta.env.DEV` ガード内。`__tcTestInsertBlock` と同じ流儀): `{ appState, activeTabId, tabs: [{ id, filename, language, content, totalEvents, pendingCount, currentHash }] }` を返す (`core/stateContract.ts` の `buildTestSnapshot`)。tabs は表示順 (`getAllTabs()`)、filename は `data-filename` と同じ拡張子込み、タブ 0 本なら `activeTabId: null`。本番ビルドには残らない (`production-build.spec.ts` が見張る)
- **dev フック `window.__tcTestForgeTemplateInjection(content)`** (同じ DEV ガード内。型は `core/stateContract.ts`): アクティブタブに任意内容の `templateInjection` を記録し、`EditorController` を detach した間に `model.setValue` して contentChange を載せない。改造クライアントが封印 starter と別の内容を雛形として注入する経路の再現で、verify 側の starter 照合 (#718) の負の対照に使う。本番ビルドに残らないことは `production-build.spec.ts` が見る
- **dev フック `window.__tcTestAuthorWorkspace`** (`/author` の dev ビルドのみ。`authoring/authorMain.ts` の `import.meta.env.DEV` ガードの中から `workspace/devWorkspaceHook.ts` を dynamic import するので、mount の後に非同期で現れる。E2E は `waitForFunction` で待つ): `openInPage(handle)` (実際の画面にフォルダを開かせ、作業画面になるまで待ってフォルダ名を返す。#796) / `document(path)` (画面が開いている文書の `{ path, savedText, text, dirty }`。開いていなければ null。#796) / `open(handle)` / `resume()` / `list()` / `read(path)` / `write(path, text, overwrite?)` (画面を通さずにフォルダを読み書きして再開を試す。#795) / `setNextPickedDirectory(handle | null)` (画面が次に開くフォルダのピッカーを 1 回だけ差し替える。コピー先の選択・フォルダを開く・新しいフォルダの親を選ぶ、の 3 か所に効く。#800) / `setFakeVerification(entries | null)` (検証の実行の入口を、対応表どおりに結果を返す偽物 `verification/fakeRunner.ts` に差し替える。null で実物に戻す。#799) / `fakeVerificationCalls()` (偽物が呼ばれた順の `{ filename, stdin }`。#799)。E2E 側の足場は [`packages/e2e/tests/helpers/author.ts`](../../e2e/tests/helpers/author.ts)。ネイティブのフォルダのピッカーは Playwright で操作できないので、テストは OPFS (`navigator.storage.getDirectory()`) のハンドルを教材フォルダとして渡す。OPFS は権限が常に `granted` なので、`prompt` の経路はユニットテストが担う。本番ビルドに残らないことは `production-build.spec.ts` が見張る (#795)
- E2E 側の読み手は [`packages/e2e/tests/helpers/app.ts`](../../e2e/tests/helpers/app.ts) の `EditorApp` (`tabs()` / `openDialogs()` / `snapshot()` / `expectConsistent()`)。`expectConsistent()` は DOM の契約と snapshot の一致 (タブの順序・id・active・filename・タブに見える名前と `data-filename` の一致 (#828)・language、アクティブなタブの件数・ハッシュ、`#language-selector` の値) を、PoSW の pending が 0 になって DOM が追いつくまで待って確かめる。**proof に記録したのに表示を更新しない経路を作ると、ここで食い違いとして落ちる**。表示 (`#event-count` / `#current-hash`) は、どのタブの TypingProof でも記録の受付と PoSW の確定のたびに `TabManager.setOnProofChange` の通知 (microtask にまとめて 1 回) で追従するので、EventRecorder を通さず proof に直接記録する経路 (export 前の attestation・contentSnapshot・テンプレート注入など) も個別に表示を更新しなくてよい (#521。それ以前は経路ごとに足していた: export の `ExportCallbacks.onProofChanged` = #439、contentSnapshot の記録後の `update()` = #448)。TypingProof を作る・復元する経路を足すときは、`setOnPendingEventChange` を直に張らず `watchProofChanges` を通す (保存と表示の追従の両方がそこにある)
