# packages/editor — 不変条件の全文

[AGENTS.md](../AGENTS.md)「重要な不変条件」の全文 (理由・例外・回帰テスト)。番号は AGENTS.md と同じで、変えない (コード・テスト・他の文書が番号で参照する)。不変条件を足す・変えるときは、ここに全文を書き、AGENTS.md には見出しを 1 行だけ置く。

`core/`・`services/`・`ui/` などで始まるコードのパスは `packages/editor/src/` から見たもの。

1. **Event #0 は `humanAttestation`**: ファイル作成時の Turnstile 認証をチェーンの根として固定する。**他のイベントを #0 にしてはいけない** (チェーン根の信頼性が崩れる)。**ADR-0017**: casual/class では Turnstile を `/api/session/start` に統合し、**initialize より先に**実行して `serverNonce` 入り ECDSA トークンを得て `TypingProof.initializeAnchored` で root をサーバアンカーする (`SHA256(fp ‖ localNonce ‖ serverNonce)`)。`#0 humanAttestation` は引き続き記録するが暗号的束縛は proof 同梱の `sessionStartToken` が担う。session/start の `sessionId` は **`sessionService.getCurrentSessionId()`** (署名 cp と同じ) を使う (verifier が token↔cp の sessionId 一致を要求)。不達時は従来 `initialize` にフォールバック (`rootAnchored:false`)。**作成時の認証全体 (Turnstile のスクリプト読込 + チャレンジ + session/start) は `TAB_CREATE_VERIFICATION_BUDGET_MS` で打ち切る** (#375): `performVerificationWithUI` に `budgetMs` を渡すと、超過で `performTurnstileVerification` を `AbortSignal` で止め (token を得る前の段階だけ。表示中のチャレンジの widget も消す)、モーダルを閉じて失敗 (`failureReason: 'timeout'`) を返す。session/start の fetch は止めず、後から届いた token は `lateSessionToken` で受けて root に焼かず `signingOnlyToken` に回す (不変条件 3)。裏で走り続ける実行が次のタブ作成の UI を書き換えないよう、`performTurnstileVerification` はフェーズ通知のコールバックを呼び出し開始時に捕まえる。casual の export 前認証は予算なしで待つ (不変条件 6。作成時とは非対称)。`createTabFromTemplate` のバンドルタブは現状非アンカー (follow-up)
2. **`EventRecorder` は fire-and-forget**: PoSW 待ちで UI をブロックしない。代わりに `queuedEventCount` を露出して UI が表示する
3. **`SignedCheckpointService` は単一フライト**: 並列 `flush()` を許すと同一 cp の二重署名で `previousSignedCheckpointHash` チェーンが破綻する ([docs/adr/0003-idempotent-signing-retry.md](../../../docs/adr/0003-idempotent-signing-retry.md))。**署名は `sessionStartToken` 前提** (ADR-0027): token はセッション単位で `TabManager.findSigningToken` が解決 (casual/class/assignment は root アンカー時の token を流用、exam は試験開始ゲート中の先行取得 (`startExamPreAttestation`) か `acquireSigningToken` が非ブロッキングで署名専用 token を取得し root には焼かない。exam の取得の失敗は `SigningTokenRetry` (`services/SigningTokenRetry.ts`) が取り直す = #236: 同時 1 本・ジッタ付き指数バックオフ (`SIGNING_TOKEN_RETRY_BASE_MS` 5 秒から倍々、`[上限/2, 上限]` の乱数、上限 `SIGNING_TOKEN_RETRY_MAX_MS` 5 分)・`online` イベントでバックオフを初期化して `SIGNING_TOKEN_ONLINE_JITTER_MS` (15 秒) の窓に散らす・オフラインの間は送らない。取得を一度も頼まれていない (exam でない) 間は `online` でも動かない。**export・保存・救出はこの成否を待たない** (呼び出しは fire-and-forget)。**`TOKEN_EXPIRED` を受けたら全モードで署名専用 token を取り直す** (#682): 期限切れと返された token は `findSigningToken` の候補から外し (`onTokenExpired` → `expiredSigningTokens`)、`SigningTokenRetry.reportRejected` で同じ規律のまま取り直す (取り直した token は `signingOnlyToken` に入れ、root には焼かない)。取り直した token がまた拒否されたら連続回数でバックオフを待つ (取得の成功では戻さず、sign が通ったら `reportAccepted` で戻す。戻すと取得 → 拒否 → 即取得が連打になる)。取得は exam と同じ UI を出さない `acquireSigningToken` なので、対話チャレンジを求められると通らずバックオフに回る。**`acquireSigningToken` は `background: true` で呼び出しごとの隠し容器に widget を描き、前面の認証 (タブ作成) の容器・チャレンジ欄・フェーズ通知に触れない** (#733: 同じ `#turnstile-widget-container` を空にして描くと、互いの widget を消して消された側がタイムアウトまで待つ)。casual/class/assignment でも、作成時の予算を過ぎてから届いた token は同じ `signingOnlyToken` に入れて `retryPendingSignatures` する = #375)。**sessionId が一致する token のうち `issuedAt` が最新のものを返す** (#227: 最初のタブの古い token を使い続けると、30 日の最大有効期間を過ぎたとき後から開いたタブの新しい token が使われない)。token が無い間は送信せず待機し、`TOKEN_INVALID`/`TOKEN_SESSION_MISMATCH` は恒久失敗として queue を空にする。**`TOKEN_EXPIRED` は恒久失敗にしない** (`tokenRejected` を立てず queue と試行回数を保つ。期限切れと返された token では再送せず、`getSessionStartToken` が別の token を返したら再開する。期限はサーバが判定し、editor の時計では判定しない。期限切れの token しか無くても `waitForFlush` は即座に抜けるので export は止まらない)。**sign の fetch は `WORKERS_FETCH_TIMEOUT_MS` で打ち切り**、タイムアウトは通常の失敗 (backoff 再試行) として `flushing` を解除する (恒久失敗にしない。#324)。**`contentHash` が空の cp (data の無いイベントに乗った cp) は enqueue しない** (署名 API が 64 桁 hex を要求して 400 で拒否し、昇順処理のため後続の署名まで止まる。失うのはその点の時刻アンカーだけ。proof の形式・verifier・Workers は変えない = #571)。**checkpoint の作成と署名の付与は `TabManager.saveToStorage` で永続化を要求する** (イベントの記録だけを保存の契機にすると、export の後に打鍵せず閉じたタブは署名前の checkpoints で復元され、index が巻き戻ってサーバと 409 で衝突する = #654)
4. **`InputDetector` の paste 検出**: `SessionContentRegistry` と照合して `insertFromPaste` (禁止) と `insertFromInternalPaste` (許可) を分ける。この判定がピュアタイピング判定の入口。**検出の範囲はイベントで分ける** (#697。`app/StaticEventListeners.ts` が `InputDetector` を 2 つ作る): **paste / copy は Monaco のコンテナ (`ctx.editor.getContainerDomNode()` = `#editor`)** で拾う (`document.body` に戻すと、ターミナル (xterm の textarea) やエディタ外のフォームへの貼り付けまでカーソル位置への externalInput になる。stdin は `terminalInput` で別に記録される)。**drop はエディタ領域のドロップゾーン (`.workbench`。テンプレートの取込とオーバーレイの範囲で、ターミナル・問題パネル・ログも含む)** で拾う (検出漏れは証明の信頼性を下げるので、Monaco の外への drop も externalInput に残す)。drop を聞く検出器は 1 つだけにする (2 か所の capture で同じ drop を二重に記録しない)。Chromium での Monaco の paste の target は EditContext の `div.native-edit-context` (それ以外は `textarea.inputarea`) で、どちらもコンテナの子孫。回帰は `app/__tests__/StaticEventListeners.inputScope.test.ts` と e2e の `terminal-paste.spec.ts`
5. **IndexedDB の書き込みは逐次**: イベント記録順序が崩れると復元時のチェーンが壊れる。**同じ `(tabId, eventIndex)` への `SessionStorageService.appendEvent` は、同じ hash の再 append だけを冪等な成功とする** (保存の再試行と、`EventRecorder` / `TabManager.saveToIndexedDB` の二重書き込みはここに入る。events も書き込み位置も書き換えない)。**hash が違えば二重インスタンスの乖離として `EventChainConflictError` で reject** し、events・位置・tabs 行を変えない (ConstraintError を黙って吸収しない。`currentHash` を後から書いた側で上書きさせない = #484 / #237)。**append は全文入りの tabs 行を書き直さない (#627)**: 書き込み位置 (`lastWrittenEventIndex` / `currentHash` / `lastModifiedAt`) は `tabProgress` ストア (keyPath `tabId`) に、events の add と同じ transaction で put する (tabs 行は `count` で有無だけを見て、行の無いタブには位置を作らない)。tabs 行を書くのは `saveTab` だけ。`getTab` / `loadTabs` は 2 つを 1 つの readonly transaction で読み、`lastWrittenEventIndex` の大きい方 (同じなら `tabProgress`) を採る (`services/tabProgress.ts` の `mergeTabProgress`)。**events を消す経路は位置も同じ transaction で消す** (`deleteTab` / `clearSession` / 飛びの切り詰めの `preserveTruncatedEvents` = #878。位置だけが残ると、同じ tabId の行に古い位置が重なる)。呼び出し側はこのエラーを握りつぶさず、`TabManager.saveToIndexedDB` は競合したタブの `saveTab` を飛ばす。復元は events 末尾の hash を正とする (#322) ので、位置を更新しない重複があっても巻き戻らない。所有者確認は `assertOwner()` (別インスタンスが `resumeSession` した後に呼ぶと `SessionOwnershipError`)。`appendEvent` の transaction 自体は sessions 行の所有者を見ない (#484 の「別インスタンスが再開した後でも、hash が合う append は通る」を保つ)。**所有権を失ったと分かったらラッチして書き込みを止める (#237 PR-3)**: `verifyOwnership()` が sessions 行の `instanceId` を自分のものと比べ、違う (または行が無い) なら `lost` としてラッチし、以後の events / tabs / sessions / tabSwitches / screenshots への書き込みを `SessionOwnershipError` で拒否する (`getWritableDb`。再読み込みまで戻らない)。読み出しと `unprovenContents` の追記 (元のコードの保全) は止めない。確認は接続の待ち行列 (`connectionReady`) に差し込むので、確認より後に呼ばれた書き込みは結果を待つ。判定できないとき (未初期化・接続なし・確認の途中で自分の `clearSession` がセッションを替えた) は `unknown` でラッチしない (譲る側を誤ると誰も記録しなくなる)。確認の契機と read-only 化 (記録・永続化・署名・スクリーンショットの停止、競合画面と救出) は `services/InstanceConflictMonitor.ts`。**チェーンに載るイベントは、確定したらその場で、確定順に `appendEvent` する (#471 / #873)**: `TabManager.saveToIndexedDB` のデバウンス保存 (100ms) は取りこぼしを埋める後ろ盾で、主経路にしない。PoSW の処理待ちが続く間は、確定のたびに `saveToStorage` がタイマーを張り直すので発火せず、その間に読み直すと保存済みの events に sequence の飛びが残って、export が検証に通らなくなる (#873 は `contentSnapshot` がこれで欠けた)。打鍵中に繰り返し記録するイベントは `EventRecorder` を通す (`recordToTab` / `recordContentSnapshot`)。proof へ直接記録してよいのは、直後に処理待ちが積もり続けない場面 (タブの作成時・問題の読み込み時・export 時の flush の前) だけ。**IndexedDB の書き込みは transaction の `oncomplete` で成功とし、`onerror` / `onabort` で失敗とする** (`IndexedDBHelper.ts` の `settleOnCommit`。request の success は commit の保証ではなく、`onabort` を待たないと commit 時に abort された書き込みが永遠に settle しない = #543)。**保存状態 (`#sync-status-item`) は永続化の成否を表す** (PoSW の処理完了とは別)。`TabManager.flushToIndexedDB()` は reject せず保存の結果を返し、export はその失敗で止めない (proof はメモリ上のチェーンから作る)
6. **エクスポート前 attestation**: `ProofExporter` の export (`exportAllTabsAsZip`。書き出しは全タブの ZIP の 1 系統で、単一タブ版は #779 で取り除いた) は Turnstile 検証 (`performPreExportVerificationForAllTabs`。記録は全タブ) を通す。ただし **exam / class は `preExportBestEffort=true`** (capabilities。assignment は casual と同じく `false`。`.tcclass` の方針が上書きする = #645。現行値は `core/__tests__/fixtures/modeCapabilities.ts` が固定する) で、Turnstile 不達/失敗でも失敗 attestation を記録して提出 ZIP を出す (ADR-0006/0011。教室の不安定網で受験者を締め出さない)。casual は従来どおりブロックする。best-effort の認証全体は `PRE_EXPORT_VERIFICATION_BUDGET_MS` で打ち切り、超過は失敗 attestation 経路に回す (casual は無期限に待つ。#324)
7. **救出は Turnstile・PoSW・IndexedDB・ネットワークの成功に依存しない。救出ファイルは proof を含まない** ([ADR-0042](../../../docs/adr/0042-rescue-code-before-proof.md)、#544): `RescueExporter` はエディタの内容とメモリ上のチェーン (`serializeState().events`) を読むだけで、待機・Turnstile・`flushToIndexedDB`・`waitForQueueDrain`・署名の `waitForFlush`・スクリーンショットを呼ばない (保存先や認証が壊れているときに押すボタンなので、どれかを待てば救出も止まる)。救出ファイル (`typedcode-rescue/2`) に `*_proof.json` を入れず、manifest に `notAProof: true` を書く (`exportProof()` も呼ばない。最終 checkpoint を作り署名を起こすので状態を変える)。1 タブの読み出しの失敗で他のタブを止めない。形式は [system-spec §5.4](../../../docs/system-spec.md)
8. **復元時に証明と食い違った元のコードを上書き・削除しない** ([ADR-0042](../../../docs/adr/0042-rescue-code-before-proof.md) 段階 2、#413): PoSW の処理待ちが残ったまま閉じると、打鍵は content にだけ残る。復元 (`TabManager.restoreContent`。整合の判断は純関数 `ui/tabs/restoredContent.ts` の `reconcileRestoredContent`) はバッファを replay 版にして proof を valid に保ち、元の content は session DB の `unprovenContents` ストアに**追記のみ** (`SessionStorageService.appendUnprovenContent` の add) で残してから返す (復元したバッファの保存より先)。このストアには put・delete の経路を作らない。`clearSession` / `deleteTab` も触らず、消えるのはリセットで DB ごと消すときだけ (保持期間は #317)。tabs の行に欄を足して持たせない (`saveTab` の put が行ごと上書きする)。保全した元のコードは復元のたびに `TabState.unprovenContents` へ読み戻し、救出は IndexedDB でなくそれを読む (不変条件 7)。保存済みのイベント列の sequence の飛び (#878) も同じストアに残す: 記録を飛びの手前で切り詰め (`ui/tabs/restoredChain.ts` の `trimRestoredChain`。残したイベントの外を指すチェックポイントも外す)、保存されていた content を `reason: 'sequence-gap'` で、飛びより後のイベントを `truncatedEvents` に写して、同じ transaction で events と `tabProgress` から消す (`preserveTruncatedEvents`。ADR-0058)。外したイベントは証明にもメモリ (`TabState.unprovenContents`) にも戻さない。元のコードをバッファへ自動で戻さない (証明と食い違う)。replay が途中で失敗するときは content を変えない
9. **起動時の空き容量の試験は、セッション DB とは別の DB に書いて消し、容量不足でも起動を止めない** (#626): `services/StorageCapacityProbe.ts` の `probeStorageCapacity` は `typedcode-storage-probe` (モード別のセッション DB と別の名前) に `STORAGE_PROBE_BYTES` の Blob を 1 行 put して commit (`settleOnCommit`) を待ち、close して `deleteDatabase` する。**開始時にも `deleteDatabase` する** (前回の試験が削除の前に落ちた残骸の掃除)。`navigator.storage.estimate()` は Chromium では空きディスクを反映しない (`usage + 10GB`) ので代わりにしない。書き込みと open の失敗のうち容量切れらしいもの (`isStorageFullError`。`cause` の連鎖まで見る) だけを `insufficient` とし、`STORAGE_PROBE_TIMEOUT_MS` 超過 (transaction を abort)・open の失敗 / blocked・それ以外の書き込み失敗は `inconclusive` で何も出さない (遅い環境や容量と無関係な失敗で警告しない)。`insufficient` のときは `initializeApp` の Phase 1.2 (利用規約の後・`initSessionStorageService` の前) で `storage-low` を出し、「このまま続ける」で必ず起動を続けられるようにする (警告であってゲートではない)。not-found 画面では走らせない (entry.ts が main.ts を読まない)。結果はハッシュチェーンに記録しない。書き込み量は dev ビルドに限り `VITE_STORAGE_PROBE_BYTES` で上書きでき (e2e は小さく縮める)、本番ビルドでは読まない。容量切れらしい失敗は `QuotaExceededError` と、`DataError` / `UnknownError` のうちメッセージが I/O の失敗 (`IOError` / `IO error` / `NO_SPACE`) のもの。**ディスクが本当に一杯のとき Chromium は `QuotaExceededError` を返さない** (#626 の実ディスクでの再現: 大きな Blob は `DataError: Failed to write blobs (IOError)`、小さな行の繰り返しは `UnknownError: … FILE_ERROR_NO_SPACE` で abort) ので、名前だけで判定しない。Chrome / Edge 専用なので Chromium の文言に合わせている。利用中の保存の容量切れらしい失敗は `TabManager.setOnStorageFull` がセッション中 1 回だけ通知し、同期状態の決め方 (`syncStatus.ts`) は変えない
