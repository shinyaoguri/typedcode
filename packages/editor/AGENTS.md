# packages/editor — AGENTS.md

`@typedcode/editor` は **キーストロークを記録して証明 ZIP を作る Monaco エディタアプリ**。

## 責務と境界

- **持つ**: Monaco との統合、イベント検出 (paste/drop/keyboard/mouse/focus/visibility)、PoSW 用 Web Worker のホスト、IndexedDB 永続化、ZIP エクスポート、Turnstile クライアント、署名済み cp の発行依頼
- **持たない**: 検証ロジック (verify 側) や暗号証明エンジン本体 (shared 側)。`TypingProof` のファサードを使うだけで、ハッシュ計算アルゴリズム自体には触らない

## 重要な不変条件

1. **Event #0 は `humanAttestation`**: ファイル作成時の Turnstile 認証をチェーンの根として固定する。**他のイベントを #0 にしてはいけない** (チェーン根の信頼性が崩れる)。**ADR-0017**: casual/class では Turnstile を `/api/session/start` に統合し、**initialize より先に**実行して `serverNonce` 入り ECDSA トークンを得て `TypingProof.initializeAnchored` で root をサーバアンカーする (`SHA256(fp ‖ localNonce ‖ serverNonce)`)。`#0 humanAttestation` は引き続き記録するが暗号的束縛は proof 同梱の `sessionStartToken` が担う。session/start の `sessionId` は **`sessionService.getCurrentSessionId()`** (署名 cp と同じ) を使う (verifier が token↔cp の sessionId 一致を要求)。不達時は従来 `initialize` にフォールバック (`rootAnchored:false`)。**作成時の認証全体 (Turnstile のスクリプト読込 + チャレンジ + session/start) は `TAB_CREATE_VERIFICATION_BUDGET_MS` で打ち切る** (#375): `performVerificationWithUI` に `budgetMs` を渡すと、超過で `performTurnstileVerification` を `AbortSignal` で止め (token を得る前の段階だけ。表示中のチャレンジの widget も消す)、モーダルを閉じて失敗 (`failureReason: 'timeout'`) を返す。session/start の fetch は止めず、後から届いた token は `lateSessionToken` で受けて root に焼かず `signingOnlyToken` に回す (不変条件 3)。裏で走り続ける実行が次のタブ作成の UI を書き換えないよう、`performTurnstileVerification` はフェーズ通知のコールバックを呼び出し開始時に捕まえる。casual の export 前認証は予算なしで待つ (不変条件 6。作成時とは非対称)。`createTabFromTemplate` のバンドルタブは現状非アンカー (follow-up)
2. **`EventRecorder` は fire-and-forget**: PoSW 待ちで UI をブロックしない。代わりに `queuedEventCount` を露出して UI が表示する
3. **`SignedCheckpointService` は単一フライト**: 並列 `flush()` を許すと同一 cp の二重署名で `previousSignedCheckpointHash` チェーンが破綻する ([docs/adr/0003-idempotent-signing-retry.md](../../docs/adr/0003-idempotent-signing-retry.md))。**署名は `sessionStartToken` 前提** (ADR-0027): token はセッション単位で `TabManager.findSigningToken` が解決 (casual/class/assignment は root アンカー時の token を流用、exam は `acquireSigningTokenBestEffort` が非ブロッキングで署名専用 token を取得し root には焼かない。casual/class/assignment でも、作成時の予算を過ぎてから届いた token は同じ `signingOnlyToken` に入れて `retryPendingSignatures` する = #375)。**sessionId が一致する token のうち `issuedAt` が最新のものを返す** (#227: 最初のタブの古い token を使い続けると、30 日の最大有効期間を過ぎたとき後から開いたタブの新しい token が使われない)。token が無い間は送信せず待機し、`TOKEN_INVALID`/`TOKEN_SESSION_MISMATCH` は恒久失敗として queue を空にする。**`TOKEN_EXPIRED` は恒久失敗にしない** (`tokenRejected` を立てず queue と試行回数を保つ。期限切れと返された token では再送せず、`getSessionStartToken` が別の token を返したら再開する。期限はサーバが判定し、editor の時計では判定しない。期限切れの token しか無くても `waitForFlush` は即座に抜けるので export は止まらない)。**sign の fetch は `WORKERS_FETCH_TIMEOUT_MS` で打ち切り**、タイムアウトは通常の失敗 (backoff 再試行) として `flushing` を解除する (恒久失敗にしない。#324)
4. **`InputDetector` の paste 検出**: `SessionContentRegistry` と照合して `insertFromPaste` (禁止) と `insertFromInternalPaste` (許可) を分ける。この判定がピュアタイピング判定の入口
5. **IndexedDB の書き込みは逐次**: イベント記録順序が崩れると復元時のチェーンが壊れる。**同じ `(tabId, eventIndex)` への `SessionStorageService.appendEvent` は、同じ hash の再 append だけを冪等な成功とする** (保存の再試行と、`EventRecorder` / `TabManager.saveToIndexedDB` の二重書き込みはここに入る。events も tabs 行も書き換えない)。**hash が違えば二重インスタンスの乖離として `EventChainConflictError` で reject** し、events・tabs 行を変えない (ConstraintError を黙って吸収しない。tabs 行の `currentHash` を後から書いた側で上書きさせない = #484 / #237)。呼び出し側はこのエラーを握りつぶさず、`TabManager.saveToIndexedDB` は競合したタブの `saveTab` を飛ばす。復元は events 末尾の hash を正とする (#322) ので、tabs 行を更新しない重複があっても巻き戻らない。所有者確認は `assertOwner()` (別インスタンスが `resumeSession` した後に呼ぶと `SessionOwnershipError`)。`appendEvent` 自体は所有者を見ない。検出時の read-only 化・UI は #237 PR-3。**IndexedDB の書き込みは transaction の `oncomplete` で成功とし、`onerror` / `onabort` で失敗とする** (`IndexedDBHelper.ts` の `settleOnCommit`。request の success は commit の保証ではなく、`onabort` を待たないと commit 時に abort された書き込みが永遠に settle しない = #543)。**保存状態 (`#sync-status-item`) は永続化の成否を表す** (PoSW の処理完了とは別)。`TabManager.flushToIndexedDB()` は reject せず保存の結果を返し、export はその失敗で止めない (proof はメモリ上のチェーンから作る)
6. **エクスポート前 attestation**: `ProofExporter` の export (`exportCurrentTab` / `exportAllTabsAsZip`) は Turnstile 検証 (`performPreExportVerification` / `…ForAllTabs`) を通す。ただし **exam/class/assignment は `preExportBestEffort=true`** (capabilities) で、Turnstile 不達/失敗でも失敗 attestation を記録して提出 ZIP を出す (ADR-0006/0011。教室の不安定網で受験者を締め出さない)。casual は従来どおりブロックする。best-effort の認証全体は `PRE_EXPORT_VERIFICATION_BUDGET_MS` で打ち切り、超過は失敗 attestation 経路に回す (casual は無期限に待つ。#324)
7. **救出は Turnstile・PoSW・IndexedDB・ネットワークの成功に依存しない。救出ファイルは proof を含まない** ([ADR-0042](../../docs/adr/0042-rescue-code-before-proof.md)、#544): `RescueExporter` はエディタの内容とメモリ上のチェーン (`serializeState().events`) を読むだけで、待機・Turnstile・`flushToIndexedDB`・`waitForQueueDrain`・署名の `waitForFlush`・スクリーンショットを呼ばない (保存先や認証が壊れているときに押すボタンなので、どれかを待てば救出も止まる)。救出ファイル (`typedcode-rescue/2`) に `*_proof.json` を入れず、manifest に `notAProof: true` を書く (`exportProof()` も呼ばない。最終 checkpoint を作り署名を起こすので状態を変える)。1 タブの読み出しの失敗で他のタブを止めない。形式は [system-spec §5.4](../../docs/system-spec.md)
8. **復元時に証明と食い違った元のコードを上書き・削除しない** ([ADR-0042](../../docs/adr/0042-rescue-code-before-proof.md) 段階 2、#413): PoSW の処理待ちが残ったまま閉じると、打鍵は content にだけ残る。復元 (`TabManager.restoreContent`。整合の判断は純関数 `ui/tabs/restoredContent.ts` の `reconcileRestoredContent`) はバッファを replay 版にして proof を valid に保ち、元の content は session DB の `unprovenContents` ストアに**追記のみ** (`SessionStorageService.appendUnprovenContent` の add) で残してから返す (復元したバッファの保存より先)。このストアには put・delete の経路を作らない。`clearSession` / `deleteTab` も触らず、消えるのはリセットで DB ごと消すときだけ (保持期間は #317)。tabs の行に欄を足して持たせない (`saveTab` の put が行ごと上書きする)。保全した元のコードは復元のたびに `TabState.unprovenContents` へ読み戻し、救出は IndexedDB でなくそれを読む (不変条件 7)。元のコードをバッファへ自動で戻さない (証明と食い違う)。replay が途中で失敗するときは content を変えない

## データフロー

```
User Action
  → InputDetector (paste/drop 検出)
  → OperationDetector (Monaco 変更 → operation 種別)
  → KeystrokeTracker / MouseTracker / ...
  → EventRecorder (キューイング、fire-and-forget)
  → TypingProof.recordEvent() [shared]
  → HashChainManager → PoswManager (Web Worker)
  → StoredEvent → IndexedDB (イベント本体) + sessionStorage (タブ状態。proof データは localStorage に置かない)
  → (cp 作成時) SignedCheckpointService → Workers /api/checkpoint/sign
```

エクスポート:

```
ProofExporter.export()
  → performSelfReview() (ADR-0022。capabilities.selfReview、exam は off。任意の reflectionNote をチェーンへ)
  → performPreExportVerification() (Turnstile。exam/class/assignment は best-effort)
  → getProofData() → ScreenshotTracker.getAllScreenshots()
  → JSZip → ダウンロード
  ── ここで export の区間 (isExporting) を閉じる ──
  → (現在のタブだけ) ZIP に入れた proof.json に verifyProofFile (fast) をかけて自己検証 → 結果の通知
```

単一フライトのガード (`isExporting`) はダウンロードまでの区間だけを閉じる。ダウンロード後の自己検証 (`verifyAfterDownload`) は区間の外で走らせ、その間に押された次の export を無視しない (#565)。自己検証は ZIP に入れたのと同じ proof.json の文字列に shared の `verifyProofFile` を `{ mode: 'fast' }` (PoSW を再計算しない) でかけた `valid` で通知を選ぶ (#586)。受理ポリシー (`require*`) は立てないので、結論は同じ ZIP を verify-cli の既定で検証したときと一致する。記録中のメモリ (`TypingProof`) ではなく ZIP と同じスナップショットを検証するので、検証の途中に次の export が同じ proof へ記録しても関係ない (`export/__tests__/ProofExporter.verifyAfterDownload.test.ts`)。検証の throw は ZIP が出た後なので `export.failed` ではなく `export.verifyFailed` で知らせる。

## 状態契約 (data-* 属性)

E2E (`packages/e2e`) は editor の UI 状態を、翻訳テキストや CSS クラスではなくここに挙げる **data-\* 属性** と dev 限定フック `__tcTestSnapshot` で読む ([ADR-0034](../../docs/adr/0034-replace-manual-verification-with-automated-tests.md)、#433)。値は生の値 (id・言語 id・enum) で、翻訳しない。既存の class (`active` / `synced` など) や表示テキストはそのまま残してあり、契約はそれに**足した**もの。

- **ユーザーの JS / TS は opaque origin の sandbox iframe 内の Worker でだけ実行する (#290 / ADR-0041)**: エディタの realm で eval しない (`new Function` / `AsyncFunction` / `eval` をエディタ側でユーザーコードに使わない)。同じ realm だと停止できず、同期ループでエディタが固まり、親 DOM・localStorage・proof の IndexedDB・`/author` の `#author-jwk` に届く。`executors/sandbox/SandboxRunner.ts` が実行ごとに `sandbox="allow-scripts"` の srcdoc iframe を作り、その中の Blob Worker で動かす。**`allow-same-origin` を足さない** (`runnerDocument.ts` の `SANDBOX_IFRAME_TOKENS`。足すと親と同じ origin になる)。停止・タイムアウト・出力予算の超過・runner の準備応答なしは **iframe の除去**で終わらせ、ユーザーコードの協力を当てにしない。親は `e.source === iframe.contentWindow` と `parseSandboxMessage` (runId と形) を通ったものだけを扱い、Worker は起動時に渡した MessagePort だけで返す。runner の CSP (`default-src 'none'; script-src 'unsafe-inline' 'unsafe-eval' blob:; worker-src blob:; connect-src 'none'`) を緩めるときは ADR-0041 を更新する。srcdoc は親の CSP を継承するので、**親に CSP を入れるとき (#411) は runner の blob: Worker と 'unsafe-eval' を塞がない**。Worker のソース (`workerSource.ts`) はバンドラの変換を受けない文字列定数で、テストは node の `vm` で評価する。`CodeExecutionController` は run ごとに番号を持ち、状態とターミナルへの出力は今の run のときだけ書く (停止 → 即再実行の競合)。E2E はタイムアウトと出力予算を dev 限定の `window.__tcExecLimits` で縮める (本番ビルドでは読まない)。回帰は `packages/e2e/tests/code-execution.spec.ts` と `production-build.spec.ts` (本番の CSP / COEP 下で動くこと)

- **IndexedDB の接続のライフサイクル (#325)**: `SessionStorageService` は open の `blocked` で待ち続けずに `SessionStorageBlockedError` で reject する (起動失敗の画面で他のタブを閉じるよう案内する。遅れて success した接続は握らずに閉じる)。開いた接続が `versionchange` を受けたら閉じて (新しい版の open を塞がない) 以後の操作を `SessionStorageUnavailableError('versionchange')` にし、強制的な `close` (サイトデータの削除など。自分の `close()` では発火しない) では 1 回だけ開き直して、失敗したら `SessionStorageUnavailableError('closed')` にする。どちらもリスナー (`setOnConnectionLost`) で main が通知を出す。**接続を失っても `initialized` と `sessionId` を落とさない**: `TabManager.saveToIndexedDB` は未初期化なら書かずに成功扱いにするので、落とすと保存の失敗が `synced` に見える (失敗は `degraded` / `failed` で出す)。各メソッドは `this.db` を直に触らず `getDb()` を経る。`getDb()` は 1 本の `connectionReady` (普段は解決済み、強制 close の後は開き直しの試み) に `.then` を連ねるので、開き直しの間に呼ばれたものも含めて呼び出し順に transaction を作る (書き込みの逐次性 = 不変条件 5)。起動処理 (`initializeApp`) の reject は `boot()` が拾って `boot-failure` を出すので、起動中の例外を握りつぶして続行しない。回帰は `services/__tests__/SessionStorageService.connection.test.ts` と e2e の `fault-storage.spec.ts`
