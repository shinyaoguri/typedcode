# ADR-0046: 学生にモードを選ばせず、`/` で練習のエディタを直接開く

- **Status**: Accepted (段階 1 = #644 を実装。段階 2 = #645・段階 3 = #646 は未着手)
- **Date**: 2026-11-06
- **Deciders**: @shinyaoguri
- **PR / Commit**: (#644 を閉じる PR)

## Context

ADR-0011 は演習授業の場面を 4 モード (casual = 練習 / class = 授業 / assignment = 課題 / exam = 試験) に分け、URL パスで分岐した。ADR-0015 は `/` を 4 モードの比較カードを並べるランディングにし、エディタの titlebar にモード切替のドロップダウン (`ModeSwitcher`) を置いた。

このため、学生は入口でモードを選び、エディタの中でも切り替えられる。しかし、モードの中身は場の方針であり、決めるのは教員である。

- **試験**は `.tcexam` (封印問題) が無いと成り立たない。実際にモードを決めているのは配布物である。
- **授業と課題**の差は、`core/mode.ts` の能力プリセットで 3 点しかない。スクショ (授業はあり、起動時に勧誘する。課題はなし)、fullscreen の受動記録、export 前の Turnstile を best-effort にするか、である。
- 検証側は自己申告の `proof.mode` を信頼の判断に使わない (ADR-0020)。学生がどのモードを選んでも安全性は変わらない。変わるのは UX と、記録する信号の範囲だけである。
- 学生が選び間違えると、方針と違う記録が残る (例: 授業で「課題」を選ぶとスクショが残らない)。
- ランディングの比較カードは「封印・根束縛」「証明保証」といった学生向けでない言葉を見せていた。証明保証の欄は課題を「中」としていたが、ADR-0011 の表では「低」であった。保証度はモードではなく実証拠から決まる (ADR-0020) ので、モードごとに保証を書くこと自体がずれていた。
- 本番の主な入口は Moodle からの直リンク (`/exam` 等) である (ADR-0015)。

#643 で方向と段階を議論し、メンテナが次を決めた。

1. 学生にモードを選ばせない。モードは配布物 (`.tcclass` / `.tcexam`) と教員が配るリンクが決める。
2. 授業と課題は、`.tcclass` に教員が入れる方針 (「教室で実施 / 持ち帰り」) で 1 つにまとめる。
3. 問題ファイルを作らない教員のために、`/class` `/assignment` `/exam` を方針だけを決める入口として残す。
4. 自由に書いている途中で問題ファイルを読み込んだら、配布物ごとに新しい作業スペースを開く。

## Considered Options

### Option A: 4 択のランディングを残し、文言だけ学生向けに直す
- Pros: 変更が最小で済む。各モードの「続きから」が入口で見える。
- Cons: 方針を学生が選ぶ構造が残る。選び間違いもエディタ内の切替も残る。

### Option B: 配布物と教員のリンクがモードを決める (★採用)
- Pros: 学生の操作は「書く」か「配られた問題を開く」だけになる。方針は教員の手元で決まる。試験の安全性は今も封印の暗号束縛 (ADR-0006) が担っており、何も変わらない。
- Cons: 段階 2 と 3 で配布物の形式と保存領域を変える必要があり、作業が大きい。

### Option C: 1 モードに統合し、能力を学生が個別にオン / オフする
- Pros: 概念が最も少ない。
- Cons: 方針の選択がモード単位から能力単位に細かくなるだけで、学生が選ぶ構造は変わらない。却下した。

## Decision

**Option B を採り、3 段階で進める。** 本 ADR の時点では段階 1 を実装した。

### 段階 1 (#644): 入口から選択をなくす
- **ルート**: `resolveRoute` は `/` と `/casual` を `casual` に、`/class` `/assignment` `/exam` を各モードに、それ以外を `'not-found'` にする。
- **`/` は練習のエディタを直接開く。** ADR-0015 のランディング (`LandingPage`)、「続きから」バッジ (`SessionDetector`)、比較カードの i18n は撤去する。
- **未知のパスは not-found 画面に落とす。** この画面は `/` へのリンクだけを出す。ADR-0015 の「タイポを黙って casual にしない」は保つ。not-found 画面はエディタの chunk を読まない (#302 の制約を引き継ぐ)。
- **titlebar のモード表示は、今の場所を示すだけにする** (`ModeBadge`)。別モードへ移るメニューは持たない。他のモードのセッションへは、教員が配ったリンクで戻る。
- **練習の規約同意**: 規約モーダルは今どおり出さない。ランディングにあった受動的な告知 (「利用を開始すると利用規約に同意したものとみなします」) は、エディタ内の通知に移す。通知の OK か規約モーダルでの同意で `markTermsAccepted()` し、開いているタブに `termsAccepted` を記録する。
- `/class` `/assignment` `/exam` の直リンクの挙動は変えない。

### 段階 2 (#645): `.tcclass` に方針を持たせ、授業と課題をまとめる
`/author` で「教室で実施 / 持ち帰り」を選んで `.tcclass` を出せるようにし、読み込んだ方針で能力を決める。`/class` `/assignment` は方針だけを決める入口として残す。

### 段階 3 (#646): 保存領域を配布物単位にする
名前空間を、モード単位 (`typedcode-{mode}`) から配布物 ID 単位に移す。練習の途中で問題を読み込んだら、配布物の作業スペースへ移る。`proof.mode` はパスではなく配布物から決める。

決め手は二つある。方針を決める人 (教員) と、選ぶ操作をする人 (学生) を一致させられること。そして、試験の安全性と証明の形式に触れずに済むこと (保証は ADR-0006 の暗号束縛と ADR-0020 の実証拠が担い、モードのラベルは信頼に使っていない)。

## Consequences

### Positive
- 学生は `/` を開けばすぐ書ける。入口で場面や保証を理解する必要がない。
- 方針と違うモードで記録する事故が、入口とモード切替の経路では起きなくなる。
- 学生向けでない言葉 (封印・根束縛・証明保証) が入口から消える。
- 証明の形式 (`PROOF_FORMAT_VERSION`)、Turnstile の `#0`、試験の封印・監督コード・根束縛には触れない。

### Negative / Trade-offs
- **`/` の意味が「ランディング」から「練習のエディタ」に戻る。** ADR-0015 の初期最適化 (`/` で Monaco 等の chunk を読まない、#302) は `/` には効かなくなり、not-found 画面にだけ残る。
- **「続きから」バッジが無くなる。** 授業・課題・試験の進行中セッションへは、教員が配ったリンク (`/class` 等) で戻る。リンクを開けばその名前空間のセッションは今どおり復元される。
- **エディタ内でモードを移る手段が無くなる。** 移りたいときは URL を開き直す。
- 練習で規約に同意した記録 (`termsAccepted`) が載るのは、通知を閉じた後か規約モーダルで同意した後になる。それより前に export した proof には載らない (`/casual` 直開きの従来の挙動と同じ)。
