# ADR-0057: 閉じたタブ・取り込みで置き換えたタブ・前のセッションを、消さずに「閉じたタブ」として残す

- **Status**: Accepted (決定 1 の例外 = 復元で見つけたイベント列の飛びより後を保全に写して events から外す、を ADR-0058 で追補 #878)
- **Date**: 2026-11-21
- **Deciders**: @shinyaoguri
- **PR / Commit**: (#317 を閉じる PR。方針の決定 D1〜D4 は #317 の 2026-11-03 のコメント)

## Context

タブを閉じる・テンプレートを取り込む・復旧ダイアログで「新規セッション」を選ぶ、のどれでも、書いたコードと記録 (イベント・チェックポイント・スクリーンショット) が IndexedDB から即座に削除されていた。確認ダイアログは出るが、押し間違い・「新規」の意味の取り違え・テンプレートの取り込みで前のタブが消えることに気付かない、といった形で、利用者が意図せず提出前の成果を失う (#306「利用者が作成したコードを失わない」)。

復元の側は #413 (証明と食い違う元のコードの保全) と #300 (救出) で「失わない」を進めてきたが、削除の側は手付かずだった。

## Considered Options

### Option A: 現状のまま (確認ダイアログで防ぐ)

- Pros: 変更が無い。保存領域が増えない
- Cons: 確認は押し間違いと取り違えを防がない。失ったものは戻せない

### Option B: 閉じたものを一定期間だけ残し、N 日後に自動で消す

- Pros: 保存領域の増え方に上限ができる
- Cons: 自動の削除は「失わない」(#306) と衝突する。期限の直後に必要になった利用者を救えない。期限を決める根拠も無い

### Option C: 閉じたものを期限なしで残し、利用者が明示で消したときだけ削除する

- Pros: 押し間違いでも戻せる。削除は利用者の明示の操作だけになる
- Cons: 保存領域が増え続ける。共有のコンピュータでは、次の利用者が前の利用者の閉じたタブを開ける

### Option D: 残すのは救出 (ZIP の書き出し) だけにし、開き直しは作らない

- Pros: 実装が小さい
- Cons: 続きを書けない。救出の UI (#300 の段階 1) を待つことになる

## Decision

**Option C** を採る (exam を除く)。

1. **exam 以外では、利用者の明示の操作なしに、コードとイベントを IndexedDB から削除しない**。明示の操作は、復旧ダイアログの「完全に削除する」と、設定メニューのリセットの 2 つ
2. **タブを閉じる・テンプレートを取り込む**と、そのタブを「閉じたタブ」にする (tabs 行に `archived: true` と `archivedAt` を付ける)。イベント・書き込み位置・スクリーンショットは残す。**最後のタブを閉じても、スクリーンショットを消さない**
3. **復旧ダイアログの「新規セッション」**は、「前回のファイルを残す (既定)」と「完全に削除する」を選ばせる。残すを選ぶと、前のセッションの開いていたタブを閉じたタブにしてから、新しいセッションを作る
4. **メインメニューの「閉じたタブ」**から、閉じたタブ (前のセッションのものを含む) を開き直せる。開き直すと、同じチェーンの続きに記録される
5. **exam は従来どおり削除する** (試験の問題と解答を端末に残さない。メニューにも出さない)

### 保存の形

- `archived` / `archivedAt` は tabs 行 (`StoredTabData`) に足す。append のたびに書き直す `tabProgress` (#627) には入れない
- **`DB_VERSION` は上げない**。列を足すだけで、旧行は欄が無いので閉じていないものとして読む。版を上げると、その版で一度開いた利用者が前の版のエディタで起動できなくなる。一覧は tabs を全件読んで絞る (index を作らない)
- 閉じるときの書き込みは **1 つの transaction** にする: メモリ上の確定したチェーンのうち、まだ保存されていないイベントの追加・tabs 行の更新・書き込み位置の更新。**失敗・中断・所有権の喪失・hash の食い違いでは何も書かず、閉じる前の行が残る** (削除へ倒れない。次の再開で、開いたタブとして戻る)。#342 の後始末の順序 (PoSW の確定 → append の完了 → 保存の完了 → 行の書き込み → Worker の終了) は変えない
- 閉じたタブは、再開の復元の対象と、復旧ダイアログの件数から外す (#145)

### 開き直したタブの署名

前のセッションのタブを今のセッションで開き直しても、**署名は、その proof が結びついたセッション (署名済みチェックポイントの sessionId。無ければ root の token の sessionId) で続ける**。今のセッションの sessionId で署名し直すと、1 つの proof の中で署名チェックポイントの sessionId が混ざり、root の token とも食い違って、検証器が拒否する (実際に E2E で確認した)。元の token が有効期間 (30 日) を過ぎていれば、そのタブの署名は止まる (未署名のチェックポイントになる。整合性の検証には影響しない)。

## Consequences

### Positive

- タブを閉じる・テンプレートを取り込む・「新規」を選ぶ、のどれでも、コードと記録が残り、開き直して続きを書ける
- 閉じる途中の失敗が、削除にも「イベントだけ増えた状態」にもならない
- 保存形式の版を上げないので、前の版への巻き戻しを妨げない

### Negative / Trade-offs

- **保存領域が増え続ける**。閉じたタブの数にも期間にも上限が無い (容量の扱いは今回の範囲外)
- **共有のコンピュータでは、次の利用者が閉じたタブを開ける**。「新規」の 2 段目に「共有のコンピュータでは完全に削除を」と書き、リセットでも消せるようにしたが、選ぶのは利用者に任せている
- **閉じてから開き直すまでの空白は、チェーンに印が無い** (開き直しのイベントを足していない)
- 開き直したタブの署名は元のセッションに結びつくので、1 つの ZIP の中で、タブごとに署名の sessionId が違うことがある (proof はタブごとで、1 つの proof の中では揃っている)
- 閉じるときに、そのタブの保存済みのイベントを全件読んで hash を比べる (長いセッションでは、閉じる 1 回の読み出しが大きい)

### Follow-ups / 残課題

- 閉じたタブの容量の扱い (件数・大きさの表示、個別の削除)
- 保存領域を配布物の単位に分ける #646 との整理
- 復旧ダイアログの相対時刻 (`just now`) が、日本語の表示でも英語のまま出る (既存)
