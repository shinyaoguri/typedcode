# ADR-0037: 新しいテスト・検査は、検証対象を壊して赤くなるのを見てから仕上げる

- **Status**: Accepted (Option C の変異検査は ADR-0040 で、shared の検証系に対する手元のコマンドとして採った)
- **Date**: 2026-11-03
- **Deciders**: @shinyaoguri
- **PR / Commit**: (#466 を閉じる PR)

## Context

[ADR-0034](0034-replace-manual-verification-with-automated-tests.md) は「CI が緑なら手動確認は不要」を目標に、テストが増え続けて減らないことを CI で強制した。仕組みはテスト必須ゲート (`require-tests`) とカバレッジのラチェットである。ただし、どちらもテストの**検証力**は見ない。

- `require-tests` は、テストファイルが変わったかどうかしか見ない
- カバレッジは、行が実行されたかどうかしか見ない。assert が弱くても、何も assert しなくても上がる

緑のテストが壊れた実装を捕まえられるかどうかは、緑を見ても分からない。壊しても緑のままのテストは、両方のゲートを通り、「CI が緑なら手動確認は不要」の前提を黙って崩す。

ADR-0034 の決定 5 は「既知バグは失敗する再現を先に置く」と決めた。しかし対象は**バグ修正だけ**で、機能追加やテスト追加で足すテストには及ばない (CONTRIBUTING.md の完了の定義・`.claude/agents/implementer.md` も同じ範囲)。

一方、実際の PR は、バグ修正以外でも検証対象を壊して赤を確かめ、本文に書いている。例:

- #457: unit の各ケースについて、誤った実装に差し替えると赤くなることを確かめ、表にしている
- #430: 修正だけを外して赤を確認したと書いている

これは慣習で、規約にも PR テンプレートにも欄が無い。書かれない PR が出ても気付けない。

## Considered Options

### Option A: 現状のまま (バグ修正だけを規約にし、ほかは慣習に任せる)

- Pros: 何も足さない
- Cons: 慣習は書かれなくなっても誰も気付かない。エージェントは規約に書かれたことしか確実には守らない

### Option B: 規約を新しいテスト・検査全般へ広げ、PR の対応表に欄を置く

- Pros: いまの慣習を正式にするだけで、新しい仕組みは要らない。PR の対応表に「何を壊したか」が残るので、レビューで検証力を確かめられる
- Cons: 手作業の自己申告で、取りこぼしは見えない。欄を埋めたかどうかを機械では見ない

### Option C: 変異検査の道具 (実装を 1 か所ずつ機械的に壊して、テストが赤くなるかを測る) を入れる

- Pros: 取りこぼしが数で見える。書いた本人が気付かない「壊しても緑」を拾える
- Cons: 重い (変異ごとにテストを回す)。AGENTS.md「新しい仕組みは実害を示せるときだけ足す」に照らすと、typedcode ではまだ実害 (壊しても緑のテストの実例) が記録されていない

### Option D: PR 本文の欄が埋まっているかを CI で検査する

- Pros: 書き漏れを機械で止められる
- Cons: 書き漏れの実害がまだ無い。欄が埋まっていても中身の正しさは見られない

## Decision

**Option B** を採る。

1. **新しいテスト・検査は、検証対象の振る舞いを一時的に壊すか、直した行を戻して、赤くなるのを見てから仕上げる**。バグ修正に限らない。壊しても緑のままのテストは書き直す
2. 何を壊して赤くなったかは、PR の受け入れ条件の対応表の「壊すと赤になるか (何を壊したか)」列に書く
3. ADR-0034 決定 5 (既知バグは失敗する再現を先に置く) はそのまま残す。決定 5 は**順序**の規約 (直す前に赤いテストを置く) で、本 ADR は**検証力**の規約 (テストが壊れた実装を捕まえることを確かめる) である

Option C は #467 で、実害を測ってから入れるかどうかを決める。Option D は書き漏れの実害が出るまで入れない。

## Consequences

### Positive

- テストの検証力が PR に記録として残り、レビューで確かめられる
- エージェントが新しいテストを書くときも、壊して赤を見る手順が規約として入る

### Negative / Trade-offs

- 手作業の自己申告で、取りこぼしは見えない (#467 で測る)
- PR の対応表が 1 列増える

### Follow-ups / 残課題

- #467: 変異検査で「壊しても緑のテスト」の実害を測り、出たら道具として常設するか決める
